# H 指令纸娃娃地文写作指南

给负责写某一个 H 指令纸娃娃地文的子代理看。你只写**文本源**并用脚本校验，不写 CSV、不跑 buildconfig、不改仓库里的任何文件——生成、构建与入库由主代理统一做。

工作目录：`tools/AI/纸娃娃指令地文/`（下文路径都相对它，命令都在仓库根目录 `c:\code\erArk` 运行）。

## 1. 产出

- `src/<行为id>.txt`：五档（`## 0 A` … `## 4 C2`）与通用（`## 通用 A` … `## 通用 C2`），共 30 组 300 条
- `src/<行为id>_无意识.txt`：8 种无意识差分（`## 睡奸 A` … `## 逆推 C2`），共 40 组 400 条
- 每组恰好 10 条，一行一条；组头格式 `## <组> <段>`；空行忽略
- **用 Write 工具写文件，用 Edit 工具改**。不要用 bash heredoc 写中文长文本（会吞反斜杠，超过约 150 行会整段失败）
- 参考范例：`src/hat_job.txt`、`src/hat_job_无意识.txt`（帽子交，用户已认可的成品）

## 2. 段：A / B1 / B2 / C1 / C2

游戏每次显示时，从 A 段抽一条，从 B 段（B1 与 B2 合在一起）抽一条，从 C 段（C1 与 C2 合在一起）抽一条，依次拼接；详细程度设置为低或中时只显示其中一两段。

| 段 | 内容 | 主语 |
| --- | --- | --- |
| A | 整体概述：这一下两人在做什么，交代体位与动作全貌 | 含 {TargetName} |
| B1 | 具体动作，博士主导：他怎么动、怎么摆弄她，加上她的即时反应 | 含 {Name} |
| B2 | 具体动作，她这一侧：她怎么动、怎么配合或迎合（无法自主时写她身体的状态与无意识反应） | 含 {TargetName} |
| C1 | 博士的感受：触感、视觉、心理 | 含 {Name} |
| C2 | 她的感受：触感、心理、身体反应（无法感知时写她的状态） | 含 {TargetName} |

**拼接一致性**：同一组里任意一条 A + 任意一条 B1/B2 + 任意一条 C1/C2 拼在一起都要说得通。所以：
- B、C 段不要写与 A 段可能矛盾的细节（A 写她跪着，B 就别写她躺着；A 不交代的东西 B 不要当成已知前提去指代）
- 不写需要看上一句才懂的指代（「刚才那样」「又一次」）
- 体位与动作类型在一个指令里要始终一致（见第 5 节）

## 3. 组：五档、通用、无意识差分

### 3.1 五档（只在她清醒、没有任何无意识状态时出现，互斥）

| 档 | 攻略程度 | 写法 |
| --- | --- | --- |
| 0 | 未陷落 | 她答应了这次 H，但没有陷落：克制、拘谨、带着羞耻或别扭，配合但不热情，身体有反应会想压住；不说情话、不称主人 |
| 1 | 思慕·恋慕 | 喜欢他：害羞、笨拙、紧张，拼命想做好，想被夸，偷偷开心 |
| 2 | 恋人·爱侣 | 熟练、主动，会挑逗、撒娇、坏笑、故意吊他胃口，甜蜜亲昵 |
| 3 | 屈从·驯服 | 先请示、照他教过的方式做，怕做不好、怕挨训，不敢停、不敢偷懒，规规矩矩 |
| 4 | 宠物·奴隶 | 称他主人，虔诚侍奉、以被使用为荣，讨精、求赏，淫乱放荡 |

「主人」只能出现在第 4 档（脚本会查）。

### 3.2 通用（不分档）

清醒时任何攻略程度都可能抽到，和本档文本混在一起抽（抽中概率约为本档的一半到三分之一）。所以通用文本的语气必须**中性**：写动作、触感、生理反应，不带任何一档特有的心态（不害羞初恋、不熟练调情、不请示、不称主人、不抗拒）。

### 3.3 无意识差分（8 种，互斥，各自只在对应状态出现）

先读 `.github/skills/text_generation_for_instruction_code_generation/无意识H前提/` 下的 `全无意识H简要说明.md` 与对应的各个 `.md`（时停解放不做）。要点：

| 组名 | 状态 | B2 / C2 怎么写 |
| --- | --- | --- |
| 睡奸 | 她睡着，全程没醒 | B2：睡梦中无意识的身体动作（翻身、蹭、收紧、抽动）；C2：睡梦中的模糊感知与身体反应 |
| 装睡 | 她中途醒了但继续装睡、默许；博士知道但不揭穿 | B2：借「翻身」「梦呓」掩护的小动作与刻意静止；C2：内心活动、强忍反应怕露馅 |
| 醉酒 | 醉得迷糊，判断力和行动力下降，本能地配合 | B2：迷糊、笨拙、没轻没重的动作；C2：醉意中的模糊感受 |
| 时停 | 时间停止，她完全静止、无感知 | B2：她静止的身体与姿态如何被利用（保持原样、被摆弄后就停在那里）；C2：她的状态（无知觉、表情停在时停前），不写感受 |
| 平然 | 被催眠，清醒但把一切当作理所当然的常识 | B2：平静自然地配合，像做日常小事；C2：把这当作正常的心理，生理反应也只当正常 |
| 空气 | 被催眠，把博士当空气完全无视，继续做自己的事 | 不具体写她在做什么，只泛写「手头的事」「眼前的事」；B2：她做自己的事时无意间造成的接触；C2：对身体异样的模糊察觉，找别的理由解释 |
| 木头人 | 体控，身体完全不能动，意识清醒 | B2：被摆好的姿势、僵直的身体、细微的颤抖；C2：屈辱、恐惧、愤怒，以及身体不由自主的反应 |
| 逆推 | 体控，身体主动热情地做，意识在抗拒 | B2：身体主动、娴熟、淫荡的动作；C2：心里抗拒、羞耻，又怕自己被快感拖下去 |

在插入类指令里，无意识状态也要符合体位：例如睡奸的骑乘位是博士把熟睡的她摆到自己身上；木头人的立位是博士扶着她僵直的身体。

## 4. 占位符

- `{Name}` 博士，`{TargetName}` 她。文中可以用「他」「她」，不要写「博士」二字
- 阴茎：A 段用 `{penis}`，B、C 段用 `{penis_s}`
- 身体部位：A 段用长短词 `{x}`，B、C 段用短词 `{x_s}`（x 见 spec 的 main / extra）
  - 长短词展开为「修饰语，修饰语的名词」，例：`{penis}` →「青筋盘绕，坚硬滚烫的勃起肉棒」，`{vagina}` →「粉嫩紧致湿润温暖，触感细腻敏感的温热蜜穴」
  - 短词展开为「形容词+名词」，例：`{penis_s}` →「硬挺肉棒」，`{mouth_s}` →「湿润小嘴」
  - 所以要按名词短语用：`{TargetName}的{mouth}`、`用{hands_s}`、`顶进{vagina_s}深处`；**不要**在占位符前再加形容词（×「湿热的{vagina_s}」）
  - 长短词里有逗号，句子要能承受：放在「的」之后作宾语或主语最稳
  - `{anal}` `{urethra}` `{legs}` `{feet}` `{clitoris}` `{throat}` 的长短词原先在数据里以「。」结尾，现已修复（去掉了句末句号）。**写作时照常把长短词放在句中**；评审也不要再报这一条
- 服装：`{TargetXxxName}` 是她此刻穿戴的那件衣物的名字（同部位穿多件时用顿号连接），三段都用同一个写法；**不要加量词**（×「这件{TargetHatName}」），不要写「帽子」「眼镜」这类泛称去指代
- spec 里没有列出的占位符不能用（脚本会查）。确实需要别的部位短词时，**不要改 `spec.json`**（全部指令共用一个文件，别的代理在同时写作），在校验命令末尾加 `--add-extra=部位1,部位2`，只对这次运行生效；之后每次校验都带上同样的参数，并在返回结果里写明追加项与理由，由主代理统一合并进 `spec.json`。不要删减 spec 里的任何规则

## 5. 指令语义

### 5.1 体位（插入类）

| 名称 | 体位 |
| --- | --- |
| 正常位 | 她仰躺，双腿分开，博士在上方面对面插入 |
| 背后位 / 后背位 | 她趴伏或跪趴，臀部抬起，博士从后面插入 |
| 对面骑乘位 | 博士躺着，她面对他跨坐在上面，由她起落 |
| 背面骑乘位 | 博士躺着，她背对他跨坐在上面 |
| 对面座位 | 博士坐着，她面对面坐在他腿上 |
| 背面座位 | 博士坐着，她背对他坐在他腿上 |
| 对面立位 | 两人站着面对面，常抬起她一条腿 |
| 背面立位 | 两人站着，博士从背后插入，她向前俯身 |
| 对面抱位 | 博士站着把她整个抱起，她面对他挂在身上 |
| 背面抱位 | 博士从背后把她抱起，托着她分开的双腿 |
| 对面卧位 | 两人侧躺面对面 |
| 背面卧位 | 两人侧躺，博士贴在她背后 |

插入部位：无后缀为小穴；「肛交」为后穴；「子宫口姦」为龟头挤进子宫口（宫颈）抽插；「子宫姦」为整根贯穿子宫口、插进子宫里抽插；「尿道姦」为插进她的尿道（游戏设定中可行）。博士躺着、坐着、站着时都不写床、椅子、墙之类的家具与场所（脚本禁用），只写姿势本身。

### 5.2 其他指令

看 spec 的 `notes`。

### 5.3 服装交

服装部位里的东西往往比名字宽：例如「帽子」这一格实际有发卡、发箍、发绳、头花、头盔、护目镜、兜帽、面罩等，一半不是帽子。所以动笔前先查清这一格到底有什么：
- `data/csv/ClothingTem.csv` 第三列为服装部位 id 的行
- `data/character/*.csv` 里 `C|<部位id>` 开头的行（干员默认服装，值在第三列）

然后只写各种衣物都说得通的动作：不写只有某一类才有的形制、材质、部件（帽交不写帽檐、内衬、布料；武器交不写刀刃、枪管）。spec 的 `forbidden` 里放这类词；你可以补充（同样不改 `spec.json`，用校验参数 `--add-forbidden=词1,词2`，并在返回结果里写明），不能删。服装交的姿势要与「她此刻穿戴着」一致（参考帽子交：一律是戴在头上时磨蹭，不摘下来）。

## 6. 硬性规则（脚本会查）

- 无半角逗号；单条不超过 90 字（按原文计，含占位符）
- 主语占位符见第 2 节；A、B 段必须写到本指令的部位（主部位短词、服装占位符或 spec 的字面部位词），且含阴茎占位符（spec 的 `penis_required` 为 false 时除外）；C 段至少含阴茎或本指令部位之一
- 本指令内不得有完全相同的两条
- 通用组不得与五档撞句：清醒时通用组和本档文本在同一个池子里抽，所以同一段里，通用组任一句与 0～4 档任一句去掉占位符后的相似度达到 0.75 即报错
- 不得照搬范例：去掉占位符后，与帽子交范例任一句的相似度达到 0.75 即判为照搬（只换了部位词、句子骨架不变的都会被查出来）。范例只用来学结构、分档语气与拼接一致性，句子要按本指令的动作重新构思
- 默认禁用词（spec 的 `allow_words` 可豁免）：
  - 地点、家具、时段：床、墙、桌、椅、沙发、办公、早安、晚安、清晨、深夜、夜晚、夜色、晨光、月光、阳光、枕头、枕上、软枕、天花板（「枕着他的手臂」可以写；比喻里也不要用「枕头」）
  - 破处与初次：初吻、处女、落红、破瓜、第一次、初次（另有专门文本）
  - 避孕：避孕套、套子、无套、生插、内射（不预设戴没戴套）
  - 射精那一下：射了、射满、灌满、喷射、射出来了、射进了、射在了、射到了、精液溅、精液喷（射精与绝顶由各自流程另外输出；可以写临近、快要忍不住）
  - 脚、鞋、袜（用户不要这类描写；足交、袜子交、鞋子交豁免）；裙（不预设她穿裙子；裙子交豁免）

## 7. 写作规则（评审会查）

- 动作、体位、插入部位与指令一致；B1 确实是博士主导、B2 确实是她这一侧；C1 是博士的感受、C2 是她的
- 五档语气分明，通用语气中性，无意识差分忠实于各自状态（尤其时停不写她的感受、空气不写她具体在做什么、木头人不写她动）
- 不预设她的衣着（她可能穿着也可能没穿，可能是裙也可能是裤）——服装交的那件衣物除外
- 不预设她的身体特征：胸的大小、头发长短、身高体型、尾巴兽耳角（这些交给占位符；尾交、蹭角、蹭耳朵本身要求的除外）
- 不写她绝顶的那一刻（绝顶有专门文本），可以写快要到了
- 不写对白剧本，不用引号；需要时用转述（「小声问他舒不舒服」）
- 同组 10 条要各不相同：动作、角度、节奏、细节都换着写，不要十条都是同一个句式换词；也不要在多组之间反复用同一套句子骨架
- 色情、具体、有感官细节，节奏紧凑；A 段建议 30～60 字
- 不要照抄该指令原有的固定地文（`data/talk/sex/<spec.dir>/<行为id>.csv` 中 adv_id 为 0 的行），可以参考其中的动作素材

## 8. 流程

1. 读本指南、本指令的 spec 块（`.conda\python.exe tools/AI/纸娃娃指令地文/gen_paperdoll.py . <行为id> --show-spec`，别读整份 `spec.json`）、范例 `src/hat_job*.txt`、无意识前提文档、该指令原有的固定地文（了解动作素材，别照抄）；服装交先按 5.3 调查该部位的衣物
2. 写 `src/<行为id>.txt` 与 `src/<行为id>_无意识.txt`（先写一个文件就校验一次，别等全部写完）
3. 校验：`.conda\python.exe tools/AI/纸娃娃指令地文/gen_paperdoll.py . <行为id> --check`（有追加项时末尾带上 `--add-extra=…` / `--add-forbidden=…`），改到输出 `问题 0 处`（缺文件时会报缺文本源，属正常）
4. 自查一遍第 7 节，再返回结果
