# 庆典料理与菜谱熟练度 · 维护指南

> 面向：后续维护/调平衡/加内容的人（含上游维护者）。
> 本文件只讲"改哪里＝改什么"，机制说明见同目录 `烹饪系统_熟练度与特技.md`。

## 1. 数据与代码的分布

| 想改什么 | 改哪里 |
|---|---|
| 庆典菜的名字/时间/难度/价格/介绍 | `data/csv/Recipes.csv`（`type=10`，cid 9001–9010） |
| 庆典菜的题库 | `data/csv/cook_question/<cid>_cook_question.csv`（每文件 3 行表头 + 82 行） |
| 庆典菜自带的会食效果 | `Script/System/Cooking_System/cooking.py` 的 `FEAST_DATA_BY_CID`（effect/mult）＋ `FEAST_EFFECT_TEXT`（文案） |
| 每菜 4 条自选候选 | `Script/System/Cooking_System/cooking_special_pool.py`（**生成物，勿手改**；改生成规则后重跑） |
| 生成规则（候选名/维度/数值文案） | `gen_special_pool_candidates.py`（开发工具，见 §5） |
| 熟练度梯级/阈值/阶名/耗时倍率 | `cooking.py`：`PROF_TIER_COUNTS`、`PROF_TIER_LETTERS/NAMES`、`PROF_TIER_PAYOFF`、`PROF_TIME_MULT_STEPS`、`PROF_PREVIEW_TIER`、`PROF_SLOT_TIER`、`PROF_EX_TIER`、`PROF_EX_UPGRADE` |
| 特技**实际生效**的地方 | `Script/Settle/default.py` → `handle_eat_add_just` 里的 `dish_special_dim` 分支；条件型（耐放/掩味）另有钩子：`cooking.handle_food_deterioration`、`default.handle_high_obscenity_failed_adjust` |
| 体型/显示（确认页、背包） | `make_food_panel.py`（确认页与槽位 UI）、`food_bag_panel.py`（背包分组） |

## 2. 加一道庆典料理（5 步）

1. `data/csv/Recipes.csv` 追加一行：cid 续号（9011）、`type=10`、时间/难度/价格照惯例
2. 新建 `data/csv/cook_question/9011_cook_question.csv`（复制任一现有文件的结构：3 行表头 + 82 行题）
3. `cooking.py`：`FEAST_DATA_BY_CID` 加 `9011: {"effect": "<效果名>", "mult": 1.0}`；`FEAST_EFFECT_TEXT` 加该效果的中文名与说明
4. 重跑候选池生成器（`cooking_special_pool.py` 覆盖 179 → 180 道）
5. 按 §4 自检

> introduce 文案口径见 §6；`mult` 是"入席者进食收益倍率"，1.0 表示不缩放。

## 3. 改一个自选特技维度

以「掩味」为例（它同时是"条件型"）：

1. **文案/维度名**：生成器里 `pick_cond` / `status_text` 改维度名与效果文案
2. **生效逻辑**：`Settle/default.py` 的 `if dish_special_dim:` 分支加一条（对**所有食用者**生效；只有「好感/信赖」要加 `and chara_id` 守卫）
3. **条件型钩子**：若效果发生在进食之外（变质、被拒收），要在对应钩子里读 `cooking.get_food_special_dim(food)`
4. **机检关键词**：`check_special_pool.py` 的 `DIM_KEYWORDS` 加"维度 → 候选名关键词"（防止旧名挂新效果）
5. 重跑生成器；按 §4 自检

## 4. 改完请自检这几件事

- [ ] 10 道庆典菜在确认页都显示「本菜特殊效果」；普通菜不显示
- [ ] 博士发起会食时入席干员吃到效果；**自身状态类博士自己也吃**，好感/信赖与怒气清零只给干员
- [ ] NPC 单独吃庆典料理：不播「庆典开席」、不吃会食效果
- [ ] 做满 25 次的菜出现「4 选 1」；30–60 次显示「当前：本菜耗时 −X%」；90 次后数值升级为 EX 档
- [ ] 同一道菜、不同特技做两份 → 背包里**分成两堆**且各自标注 `[特技名]`
- [ ] 老存档能正常读入（新字段有回落：`getattr(food,"dish_special","")`）
- [ ] 变质/掩味/调味接受三条老链路不被新维度带偏

## 5. 生成器与检查器（开发工具，不随游戏发布）

候选表由确定性脚本生成（同一份输入必得同一份输出），配套还有设计表机检与原生结算路径的功能验证；
它们属于开发期工具、不随游戏发布，需要时可向 PR 作者索取。

## 6. 文案口径

- **introduce**：势力锚点 ＋ 2–3 件独有物 ＋ 保留情绪收尾；54–73 字；不用 ASCII 逗号
- **效果名**：名字与效果同生同死——不要复用语义已变的旧名（历史教训：fire/batch/本菜谱大师）
- **效果文案**：统一「作用范围：触发时机 对象 方向数值」（倍率用 ×、绝对值用 −N）；名字保留不要改（候选名存在存档里，改名＝老档失配）
- **多语言**：候选名与效果文案都在 `data/csv/Dish_Special.csv`，`name/base/ex` 三列已标 `get_text=1`，会进 `.po`

## 7. 已知留白

- 干员/博士专属特效：**考虑过，本次暂时不做**，以后可以再议
- 数值（掩味 ×0.35/×0.2、抚慰 比例 10%/15% 与下限 1500、轻食半饱、体力气力 +15%）都可调，改法与 §1 表一致
- **掩味的真实收益**：被喂特殊调味且判定失败时，effect152 给约 +10000~15000 反感；第二结算按 **反感×5** 计入反发刻印门槛（10000/30000/80000）
  ⇒ 对**精液类调味（11 巧妙混入 / 12 不作掩饰）**：无掩味第 1 次就到**刻印 2 级**；掩味（非EX，×0.15）第 2 次到 1 级；**掩味 EX（×0.08）连续 4 次仍是 0 级**
  ⇒ 药剂类（调味 ≥100）掩味 ×0.35、EX ×0.2
