# 道具系统设计文档

## 概述

`Script/System/Item_System/` 是独立道具玩法的子系统目录。当前包含**避孕套道具系统**：将避孕套从单一的避孕消耗品扩展为"存量记录 / 身体装饰 / 饮用 / 挤出"的完整玩法。

## 文件结构

```
Script/System/Item_System/
├── condom_handle.py      # 避孕套存量池/装饰的数据操作工具函数
├── condom_panel.py       # 避孕套选择面板（多选 + 部位选择）
└── 道具系统设计文档.md    # 本文档
```

## 数据结构

| 数据 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- |
| 存量池 `used_condoms` | 玩家 `pl_collection`（`PLAYER_COLLECTION`） | `List[int]` | 用过的避孕套存量池，每个元素为该套内的精液量(ml) |
| 装饰 `condom_decoration` | **各角色自己的 `dirty`（`DIRTY`）** | `Dict[tuple, List[int]]` | 键为`(部位类型, 部位cid)`（部位类型 0=身体仅头发0，1=服装部位），值为各套精液量列表 |
| 行为目标标记 `condom_cloth_flag` | 玩家 `sp_flag`（`SPECIAL_FLAG`） | `int` | 当前避孕套装饰相关行为的目标类型，0=身体部位（头发），1=服装部位；由 `condom_handle.settle_*` 在面板结算时写入，供口上前提区分 |

> 注意：存量池**不能**放 `BODY_H_STATE`（h_state），因为 H 结束时 `attr_calculation.get_h_state_reset` 会重建该结构体导致数据丢失。装饰放 `DIRTY` 是安全的：`get_dirty_reset` 为原地重置已知字段，不会动 `condom_decoration`。

## 生命周期

1. **生成**：戴套射精时（`Script/UI/Panel/ejaculation_panel.py` 的戴套分支）调用 `condom_handle.add_used_condom(semen_count)` 存入存量池。
2. **清零**：玩家或玩家的交互对象**首次进入 H** 时（`Script/Settle/default.py` 的 `handle_h_flag_to_1`）调用 `clear_used_condoms()` 清空存量池；**装饰不清**。
3. **装饰去除**（丢弃，不回池）：
   - **服装部位**：衣物离开身体（换衣/洗衣/脱衣）时去除，头发上的不受影响。钩子：`Script/Design/clothing.py` 的 `get_npc_cloth` / `get_cloth_from_dormitory_locker` / `get_all_cloth_off` / `get_cloth_wear_zero_except_need`；`Script/Settle/default_cloth.py` 的 `handle_wear_to_shower_locker`（全部位）/ `handle_foot_cloth_to_shower_locker`（袜子鞋子部位10/11）
   - **污浊重置时全部清空**：`attr_calculation.get_dirty_reset` 内统一执行 `dirty_data.condom_decoration = {}`，因此角色洗澡（`handle_dirty_reset_in_shower`）或污浊全归零（`handle_dirty_reset`）时，身上全部装饰（头发+服装）一并清空（洗澡时服装装饰通常已被脱衣钩子先行清除）

## 四个指令

同一功能按模式拆为两套指令，共用行为、面板与结算：**H 版**为 SEX 类 / ITEM 子类（`h_mode_show_type=2`，前提含 `TARGET_IS_H`）；**非H版**为 OBSCENITY（猥亵）类 / ITEM 子类（`h_mode_show_type=1`，前提含 `NOT_H` 与合意前提 `T_NORMAL_56_OR_UNCONSCIOUS_FLAG`）。

| H版 cid / instruct_id | 非H版 cid / instruct_id | 行为cid | 面板结算函数 | 功能 |
| --- | --- | --- | --- | --- |
| 6429 `hang_condom_decoration` | 5047 `hang_condom_decoration_daily` | 475 | `settle_hang` | 存量池选套 + 选部位（头发/已穿着服装部位）挂为装饰 |
| 6430 `take_back_condom_decoration` | 5048 `take_back_condom_decoration_daily` | 476 | `settle_take_back` | 从对方装饰中选取，转回存量池 |
| 6431 `drink_condom_semen` | 5049 `drink_condom_semen_daily` | 477 | `settle_drink` | 选套消耗，每套 10% 入口腔(2)、90% 入胃(15)，加精液经验24/饮精经验25与口喉快感，`shoot_position_body=15` 联动饮精绝顶 |
| 6432 `squeeze_condom_semen` | 5050 `squeeze_condom_semen_daily` | 478 | `settle_squeeze` | 选套消耗 + 选部位，全额精液转移到该身体/服装部位（身体部位追加自然流动） |

执行流程（8 个 handler 共用 `handle_instruct.handle_condom_instruct_common`）：

1. **实行值判定**：先调 `instuct_judege.calculation_instuct_judege(0, 目标id, _("严重骚扰"))` 进行"严重骚扰"难度判定。判定必须在打开面板**之前**（面板确认时会直接结算数据）。-1 → 中止；0（失败）→ 结算为严重骚扰失败行为 `HIGH_OBSCENITY_ANUS` 后中止；通过 → 下一步。
2. 打开 `condom_panel.Condom_Select_Panel`；**面板在玩家确认选择时直接调用 `condom_handle.settle_*` 完成数据结算**（不经过行为结算器，无临时变量传递），取消则返回 -1 中止。
3. 处理函数走 `chara_handle_instruct_common_settle` 推进时间并触发口上（不传 judge，避免二次判定）。

> 注意：`Behavior_Effect.csv` 中 4 个行为挂**空结算 `9999`**——`settle_behavior.py` 只对存在于该表的行为触发口上，这些行不能删除。

挤出指令的目标身体部位排除口腔(2)/子宫(7)/胃部(15)（内腔走饮用），尾巴(12)/兽角(13)/兽耳(14)需对方有对应素质。

精液写入统一走 `ejaculation_panel.update_semen_dirty(..., update_shoot_position_flag=False)`。

## 显示

- 详细描述文本：`data/ui_text/condom_dirty.csv`（构建后经 `game_config.ui_text_data['condom_dirty']` 访问），键格式 `{部位名}避孕套装饰{等级}`，覆盖头发 + 全部 14 个服装部位。等级由 `condom_handle.get_decoration_level(个数)` 换算：1级=1个，2级=2个，3级=3-5个，4级=6-10个，5级=10个以上。
- Tk：`Script/UI/Panel/dirty_panel.py`（污浊栏头发部位：开启详细污浊信息时显示等级描述文本，该部位已有污浊信息时先换行再显示；未开启时显示个数。H 末尾汇总处另显示存量池明细与对方各部位装饰个数）、`Script/UI/Panel/cloth_panel.py`（各服装部位同上规则）
- Web：`Script/System/Web_Draw_System/status_panel.py`（服装条目 `dirty_text` 与头发部位 texts，同样按详细/简略切换）
- 显示处统一经 `condom_handle.get_decoration_count(...)` / `get_decoration_dict(...)` / `get_decoration_level(...)` 取数

## 口上前提

挂装饰/取回装饰/挤出三个行为的口上（`data/talk/sex/item/`）按前提 `CONDOM_OPERATION_TO_BODY` / `CONDOM_OPERATION_TO_CLOTH` 区分身体（头发）与服装两类描述；饮用口上仍用 `high_1`。前提读取玩家 `sp_flag.condom_cloth_flag`。

## 旧存档兼容

`Script/Core/save_handle.py` 载入时对每个角色回填 `pl_collection.used_condoms` 与 `dirty.condom_decoration`；`condom_handle.check_collection_data()` / `check_dirty_data()` 在每次数据访问前也做兜底回填。

## 已知边界

- 装饰记录跟随"服装部位"而非具体衣物；同部位多件衣服不区分。
- Web 模式下通过界面直接脱单件衣服（`web_server.py`）暂未挂装饰去除钩子，装饰会保留到下次整体换衣。
- `condom_decoration` 内层键为 tuple，pickle 存档无碍，未来若做 JSON 导出需转换键格式。

## 扩展指南

新增其他道具玩法时，在本目录下按 `<道具名>_handle.py` / `<道具名>_panel.py` 的命名新增模块，数据结构优先挂 `PLAYER_COLLECTION` 或角色结构体顶层，并在本文档补充说明。
