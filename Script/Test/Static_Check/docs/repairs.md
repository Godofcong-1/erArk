# 修复规则

## 原则

修复只在载入存档后执行一次，作用于已经写入 `cache` 的存档数据。每条修复挂在一条检查上（`repair.py` 的 `register_repair(check_id, repair_name)`），由写这条检查的人一并提出，并且必须同时满足：

- 答案唯一：给定当前状态，正确值只有一个，不需要猜测玩家意图。
- 保守：修改不会破坏其他不变量，也不会丢失玩家可感知的进度。
- 可留痕：每条修复记录对象、主字段、旧值、新值，写入修复日志（见 [logging.md](logging.md)）。一条修复顺带改动的其他字段不单独记录。

语义模糊时宁可只检查不修复。有些修复会复用游戏自己的函数（例如岗位集合重算调用 `basement.update_work_people()`，宿舍重分配调用 `Dormitory_System/common.py` 的选房函数），修复层调用的游戏逻辑只有这两处。

`debug_mode` 打开时整体跳过修复：debug 面板可能有意制造异常状态，不能自动改回。检查在 debug 下照常运行，由各条检查自行决定是否豁免。

| BODY-35 | 个人服装模板列表无效项清除 |
| ISLAND-09 | 岗位集合按在编名单重算 |
| ISLAND-20 | 普通宿舍超员住户重新分配。只搬迁本就该住普通宿舍的住户（`get_residence_type()` 返回 `"dormitory"`）。访客、囚犯、同居助理、舍管、监狱长一律跳过：他们的 `dormitory` 落在普通宿舍房里本身是另一种不一致，改分房间会同时踩坏 PLACE-24 与囚犯牢房唯一性 |

| ISLAND-29 | 监狱长悬空引用修正 |

| HGROUP-12 | 「群交自慰」残留标记归零 |

服装 id 跨位置重复（穿着、大浴场衣柜、宿舍衣柜）不检查也不修复：容器里存的是模板编号而不是实体，重复无法判定为错误，而按位置优先级去重对携带专属内衣的角色有害。理由见 `check_body.py` 中 BODY-05 的注记。
