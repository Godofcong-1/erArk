# 静态检查系统

## 这是什么

游戏有时会进入“逻辑上不该出现，但当下不会崩溃”的状态，例如两个互斥标记同时为真、场景名册和角色位置对不上。玩家很难描述这类问题，开发者也难复现。静态检查系统用来抓住这类状态。

“静态”指它只看某一时刻的游戏状态（内存里的 `cache`）是否自洽，既不推进游戏，也不改数据。每条检查是一条不变量：健康的游戏状态应当满足的命题。检查失败说明某处状态偏离了约定。

## 怎么检查

系统设置里的“是否开启游戏状态自检”打开后，玩家每次回到主场景等待输入前，系统把全部不变量算一遍。失败时，系统把失败内容、最近输入和涉事状态快照写进游戏目录下的日志，并提示玩家把日志交给开发者。同一条检查每个游戏版本只详写一次。

## 怎么修复

载入存档时，系统修复少数已知的存档数据异常。修复规则由写检查的人随检查一起提出：说得清“正确值只有一个，改过去不会伤到别的数据”才允许附带一条修复；说不清就只检查、不修复。每条修复都写进日志。

## 首要保证

入口绝不抛异常，绝不阻断游戏。检查失败、检查本身出错、修复失败、日志写不进去，后果只能是少一条诊断信息。开关默认关闭，关闭时本包不会被导入。
