## 1. 本期目标

取自总纲 §1 的第 3、8、10 条：

1. 可定义若干套日常日程模板并批量套用到多个孩子，单孩可微调
2. 幼女期（素质 102）未排课的节次跟随母亲，见学母亲当前工作对应的科目
3. 成年时（素质 103→104）结算性格选边、身体发育与职业倾向提示

**验收标准**：多孩可套模板并一键复制；幼女会跟着母亲去她的工作岗位并获得对应科目经验；成年时出性格选边与职业倾向文本。

## 2. 本期专属现状调查

全局现状调查见**总纲 §2**，本节只补本期实施时最需要盯住的三处。

### 2.1 `entertainment_type` 是每日随机重掷的

`entertainment.entertainment_type: list = [0, 0, 0]`（`game_type.py:894`）是每个角色的三时段日程，由 `handle_npc_ai.py:788~841` **每日随机刷新**，消费点在 `:388` 与 `:616`。

⚠️ 固定日程必须在刷新**之后**覆盖，否则当天就被随机值冲掉。这是本期唯一的时序硬约束（总纲 §2.3-3）。

### 2.2 有现成的覆盖范式

`egg_handle.replace_entertainment_for_eggs`（妊娠系统文档 §5）就是在 past_day_settle 的娱乐刷新之后替换某个时段——照抄它的挂点即可，不需要新造钩子。

### 2.3 跟随标记会被移动逻辑清零

`character_move.py:172~173` 会清 `sp_flag.is_follow`。该字段是"跟随玩家"的语义，本期的"跟随母亲"**另建字段**（口径 6，字段定义见一期方案 §4.1 的 `follow_mother_flag`）。

### 2.4 成年结算有现成的位置与范式

`Script/System/Pregnancy_System/pregnancy_handle.py:637 check_grow_to_girl` 是成年判定的唯一入口，内部已调 `chest_grow`（`:721`）与 `body_part_grow` 做发育判定并输出文本。`chest_grow` 的「母亲属性 → 概率表 → 孩子素质」结构就是本期性格选边可以照抄的范式。

⚠️ 该函数的守卫是 `handle_self_is_loli`，结算后 `talent[103] = 0` 使前提不再满足，**天然幂等**，不需要额外的防重复触发。

## 3. 设计决策

### 3.6 日程用「模板 + 每孩引用」两层

结构定义见**一期方案 §4.2** 的 `Rhodes_Island.child_schedule_template` 与 §4.1 的 `CHILD_GROWTH.schedule_template_id` / `schedule_override`（一期已建字段，本期开始写入）。

孩子身上只存模板编号与可选覆盖，模板本体全局共享一份。这样"给三个孩子都改成玩乐优先"是改一个模板，不是改三份日程——这正是口径 4「操作量不随孩子数翻倍」的落点。

**执行链**：复用 `replace_entertainment_for_eggs` 模式，在 past_day_settle 的娱乐刷新**之后**改写 `entertainment_type`（§2.1 的时序硬约束）。

⚠️ **日程管的是"没有课的时段"**；有课的节次由课表优先，日程不生效。两者的粒度不同——课表按 45 分钟的节次排，日程按 `entertainment_type` 的三个时段排，改写时只覆盖该时段内完全没有课的情况。

**四套预设模板**（口径 18）：

| 模板 | 上午 | 下午 | 晚上 | 定位 |
| --- | --- | --- | --- | --- |
| 学业优先 | 自习 | 自习 | 读书 | 没课也在学，代价是心情下滑更快（喂给翘课判定，一期方案 §3.19） |
| 均衡 | 自习 | 兴趣活动 | 自由玩耍 | 默认推荐 |
| 玩乐优先 | 兴趣活动 | 兴趣活动 | 自由玩耍 | 心情好、成长慢 |
| 自定义 | 玩家逐时段指定 | | | |

**新增的日程活动 id**：日程槽位的活动 id 复用 `Entertainment` 配置 id，本期需要往该表加**三行**——「跟随母亲」「自由玩耍」与**「自习」**。⚠️ 三行的 `class_ok` 都配 0（一期方案 §4.4 新增的列），它们是日程活动而不是兴趣课。

⚠️ **「自习」是实施时才发现要加的**（实施文档 §6.1 偏离 1）：自习一直只是个**行为**（`self_study` 211），从来没有对应的娱乐配置，「学业优先」模板排不上去。补的这一行零新代码——移动复用 561 `MOVE_TO_CLASS_ROOM`（查不到课表时本就回落随机一间理论教室）、执行复用一期的 713 `EDUCATION_SELF_STUDY`、结算复用 548（查不到课表时回落学识）。

⚠️ 上表的「兴趣活动」在配置里没有同名项（它是类别不是活动），预设模板实取「下棋」（58）作为代表。预设表按**名字**反查 cid 而不是钉死数字，因为娱乐编号会随内容增删漂移。

### 3.8 成年结算只保留性格、外貌与职业倾向

能力已在一期做成即时成长（一期方案 §3.1），所以成年时（`check_grow_to_girl`）只做三件事，照 `chest_grow` 的位置与文本输出模式：

1. **四对性格素质按 `personality_point` 符号选边**，写入 `talent[271~278]`。⚠️ **正负两侧的顺序以一期 `growth_panel.PERSONALITY_PAIR_NAME` 为准**（实施文档 §6.1 偏离 6）：pair0 正→271 勤劳 / 负→272 懒散，pair1 正→**274 坚强** / 负→**273 脆弱**，pair2 正→275 热情 / 负→276 孤僻，pair3 正→**278 开放** / 负→**277 羞耻**。一期面板已是既成事实，按本节原先的文字顺序写会导致"面板显示偏坚强、结算却写了脆弱"
2. **`care_point` 参与既有 `chest_grow` 的发育判定**，作为除母亲属性外的第二输入。⚠️ **`body_part_grow` 不接**（实施文档 §6.1 偏离 5）：读代码确认它没有任何概率判定——臀/腿/足是"直接继承母亲的素质，母亲为0时母女一起随机取一个"，没有可被照料值推动的量，硬塞偏移等于改写它的语义。折算口径：每 5 点照料值换 1 个百分点，收窄 `chest_grow` 里"不长"那一档的窗口，上限 20 点
3. **按当前能力最高的科目反查 `WorkType.csv` 的 `ability_id` 给出职业倾向提示**——"她在料理上的天赋最突出，或许适合去厨房"

⚠️ **只提示、不自动任命**。成年后成为普通干员、可任命到任何岗位（口径 39），任命权仍在玩家手里。

⚠️ `personality_point` 全为 0 时（玩家全程没参与养成事件、也没做过差异化照料）不写任何性格素质，输出"性格尚未定型"的文本，而不是随机选边。

### 3.24 幼女跟随母亲：新字段 + 新行为 + 见学结算

**为什么不复用 `sp_flag.is_follow`**（口径 6）：那是"跟随玩家"的语义，且 `character_move.py:172~173` 会在移动时清零。本期用一期已建好的 `CHILD_GROWTH.follow_mother_flag`。

**触发条件**：角色持素质 102（幼女）+ 当前节次未排课 + 母亲有效。

**新增行为**：`follow_mother`「跟随母亲见学」，60 分钟，NPC 触发（非玩家指令）。

**见学结算**：

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 学什么 | 母亲当前工作对应的 `ability_id` | `WorkType.csv` 第 7 列 |
| 基础值 | 6 | 一期方案 §3.9 的数值表；约为理论课（20）的三成 |
| 速度系数 | 按母亲该能力等级走一期方案 §3.1 的曲线 | 与教室课同一套公式 |
| 附带 | `care_point` 少量累加；母女好感与亲密 | |

**母亲无效时的回落**（⚠️ 必须每一条都有出路，否则幼女会卡在 `SHARE_BLANKLY`）：

| 情形 | 判据 | 回落 |
| --- | --- | --- |
| 没有母亲 | `relationship.mother_id == -1` | 在育儿室自由玩耍 |
| 母亲已死亡 | `game_type.py:1668` 的 `dead` | 同上 |
| 母亲在 H / 监禁 / 无意识 | `game_type.py:795`、`:817` | 同上；⚠️ **绝不能让幼女跟进 H 场景** |
| 母亲在外勤 / 外交访问 | `sp_flag.field_commission` / `sp_flag.in_diplomatic_visit` | 同上 |
| 母亲住院 | `rhodes_island.medical_hospitalized`（实施时补，见实施文档 §6.1 偏离 4） | 在育儿室自由玩耍 |
| 母亲所在场景不可达 | 场景不在 `cache.scene_data` 里（未解锁/已拆除，实施时补） | 同上 |
| 母亲没有工作（`work_type == 0`） | `WorkType.csv` cid 0 | 跟着母亲但不产生见学经验，只加 `care_point` 与好感 |

⚠️ **母亲在 H 时的回落是硬要求，不是优化**：既有的跟随链不会主动判 H 状态，本期必须显式加这一条。

## 5. 界面与信息架构

### 5.1 日程模板面板

入口与一期的课表面板并列，同样挂教育区办公室场景（口径 19）。

```
日程模板
--------------------------------------------------
编号  模板名      上午        下午        晚上      套用中
 1   学业优先    自习        自习        读书       1 人
 2   均衡        自习        兴趣活动     自由玩耍    2 人
 3   玩乐优先    兴趣活动     兴趣活动     自由玩耍    0 人
 4   自定义      --          --          --        0 人
--------------------------------------------------
[编辑模板]  [批量套用到多个孩子]      <- [返回] 由页签容器统一提供，见一期方案 §9.2
```

「批量套用到多个孩子」走既有的通用 NPC 选择面板（`.github/prompts/数据处理工作流/通用NPC选择面板.md`），多选后一次套用——这是口径 4 的核心操作。

### 5.2 单孩微调

在一期的个人课表面板（一期方案 §5.3）里加一行"日程模板：均衡 [改]"，点进去可对该孩子单独覆盖某个时段，覆盖值存 `schedule_override`，不影响模板本体与其他孩子。
