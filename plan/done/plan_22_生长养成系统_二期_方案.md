## 2. 本期专属现状调查

全局现状调查见**总纲 §2**，本节只补本期实施时最需要盯住的三处。

### 2.1 `entertainment_type` 是每日随机重掷的

`entertainment.entertainment_type: list = [0, 0, 0]`（`game_type.py:894`）是每个角色的三时段日程，由 `handle_npc_ai.py:788~841` **每日随机刷新**，消费点在 `:388` 与 `:616`。

固定日程必须在刷新**之后**覆盖，否则当天就被随机值冲掉。这是本期唯一的时序硬约束（总纲 §2.3-3）。

### 2.2 有现成的覆盖范式

`egg_handle.replace_entertainment_for_eggs`（妊娠系统文档 §5）就是在 past_day_settle 的娱乐刷新之后替换某个时段——照抄它的挂点即可，不需要新造钩子。

### 2.3 跟随标记会被移动逻辑清零

`character_move.py:172~173` 会清 `sp_flag.is_follow`。该字段是"跟随玩家"的语义，本期的"跟随母亲"**另建字段**（口径 6，字段定义见一期方案 §4.1 的 `follow_mother_flag`）。

### 2.4 成年结算有现成的位置与范式

`Script/System/Pregnancy_System/pregnancy_handle.py:637 check_grow_to_girl` 是成年判定的唯一入口，内部已调 `chest_grow`（`:721`）与 `body_part_grow` 做发育判定并输出文本。`chest_grow` 的「母亲属性 → 概率表 → 孩子素质」结构就是本期性格选边可以照抄的范式。

该函数的守卫是 `handle_self_is_loli`，结算后 `talent[103] = 0` 使前提不再满足，**天然幂等**，不需要额外的防重复触发。

## 3. 设计决策

### 3.6 日程用「模板 + 每孩引用」两层

结构定义见**一期方案 §4.2** 的 `Rhodes_Island.child_schedule_template` 与 §4.1 的 `CHILD_GROWTH.schedule_template_id` / `schedule_override`（一期已建字段，本期开始写入）。

孩子身上只存模板编号与可选覆盖，模板本体全局共享一份。这样"给三个孩子都改成玩乐优先"是改一个模板，不是改三份日程——这正是口径 4「操作量不随孩子数翻倍」的落点。

**执行链**：复用 `replace_entertainment_for_eggs` 模式，在 past_day_settle 的娱乐刷新**之后**改写 `entertainment_type`（§2.1 的时序硬约束）。

**日程管的是"没有课的时段"**；有课的节次由课表优先，日程不生效。两者的粒度不同——课表按 45 分钟的节次排，日程按 `entertainment_type` 的三个时段排，改写时只覆盖该时段内完全没有课的情况。**（2026-09-10 §9.2.9 已改：改写不再避让有课的时段，课表在节次级别优先）**

**四套预设模板**（口径 18）：

| 模板 | 上午 | 下午 | 晚上 | 定位 |
| --- | --- | --- | --- | --- |
| 学业优先 | 自习 | 自习 | 读书 | 没课也在学，代价是心情下滑更快（喂给翘课判定，一期方案 §3.19） |
| 均衡 | 自习 | 兴趣活动 | 自由玩耍 | 默认推荐 |
| 玩乐优先 | 兴趣活动 | 兴趣活动 | 自由玩耍 | 心情好、成长慢 |
| 自定义 | 玩家逐时段指定 | | | |

**新增的日程活动 id**：日程槽位的活动 id 复用 `Entertainment` 配置 id，本期需要往该表加**三行**——「跟随母亲」「自由玩耍」与**「自习」**。三行的 `class_ok` 都配 0（一期方案 §4.4 新增的列），它们是日程活动而不是兴趣课。

**「自习」是实施时才发现要加的**（实施文档 §6.1 偏离 1）：自习一直只是个**行为**（`self_study` 211），从来没有对应的娱乐配置，「学业优先」模板排不上去。补的这一行零新代码——移动复用 561 `MOVE_TO_CLASS_ROOM`（查不到课表时本就回落随机一间理论教室）、执行复用一期的 713 `EDUCATION_SELF_STUDY`、结算复用 548（查不到课表时回落学识）。

上表的「兴趣活动」在配置里没有同名项（它是类别不是活动），预设模板实取「下棋」（58）作为代表。预设表按**名字**反查 cid 而不是钉死数字，因为娱乐编号会随内容增删漂移。

### 3.8 成年结算只保留性格、外貌与职业倾向

能力已在一期做成即时成长（一期方案 §3.1），所以成年时（`check_grow_to_girl`）只做三件事，照 `chest_grow` 的位置与文本输出模式：

1. **四对性格素质按 `personality_point` 符号选边**，写入 `talent[271~278]`。**正负两侧的顺序以一期 `growth_panel.PERSONALITY_PAIR_NAME` 为准**（实施文档 §6.1 偏离 6）：pair0 正→271 勤劳 / 负→272 懒散，pair1 正→**274 坚强** / 负→**273 脆弱**，pair2 正→275 热情 / 负→276 孤僻，pair3 正→**278 开放** / 负→**277 羞耻**。一期面板已是既成事实，按本节原先的文字顺序写会导致"面板显示偏坚强、结算却写了脆弱"
2. **`care_point` 参与既有 `chest_grow` 的发育判定**，作为除母亲属性外的第二输入。**`body_part_grow` 不接**（实施文档 §6.1 偏离 5）：读代码确认它没有任何概率判定——臀/腿/足是"直接继承母亲的素质，母亲为0时母女一起随机取一个"，没有可被照料值推动的量，硬塞偏移等于改写它的语义。折算口径：每 5 点照料值换 1 个百分点，收窄 `chest_grow` 里"不长"那一档的窗口，上限 20 点
3. **按当前能力最高的科目反查 `WorkType.csv` 的 `ability_id` 给出职业倾向提示**——"她在料理上的天赋最突出，或许适合去厨房"

**只提示、不自动任命**。成年后成为普通干员、可任命到任何岗位（口径 39），任命权仍在玩家手里。

`personality_point` 全为 0 时（玩家全程没参与养成事件、也没做过差异化照料）不写任何性格素质，输出"性格尚未定型"的文本，而不是随机选边。

### 3.24 幼女跟随母亲：新字段 + 新行为 + 见学结算

**为什么不复用 `sp_flag.is_follow`**（口径 6）：那是"跟随玩家"的语义，且 `character_move.py:172~173` 会在移动时清零。本期用一期已建好的 `CHILD_GROWTH.follow_mother_flag`。

**触发条件**：角色持素质 102（幼女）+ 当前节次未排课 + 母亲有效。

**新增行为**：`follow_mother`「跟随母亲见学」，60 分钟，NPC 触发（非玩家指令）。

**见学结算**：

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 学什么 | 母亲当前工作对应的 `ability_id` | `WorkType.csv` 第 7 列 |
| 基础值 | 6 | 一期方案 §3.9 的数值表；约为理论课（20）的三成 |
| 速度系数 | 按母亲该能力等级走一期方案 §3.1 的曲线 | 与教室课同一套公式 |
| 附带 | `care_point` 少量累加；母女好感与亲密 | |

**母亲无效时的回落**（必须每一条都有出路，否则幼女会卡在 `SHARE_BLANKLY`）：

| 情形 | 判据 | 回落 |
| --- | --- | --- |
| 没有母亲 | `relationship.mother_id == -1` | 在育儿室自由玩耍 |
| 母亲已死亡 | `game_type.py:1668` 的 `dead` | 同上 |
| 母亲在 H / 监禁 / 无意识 | `game_type.py:795`、`:817` | 同上；**绝不能让幼女跟进 H 场景** |
| 母亲在外勤 / 外交访问 | `sp_flag.field_commission` / `sp_flag.in_diplomatic_visit` | 同上 |
| 母亲住院 | `rhodes_island.medical_hospitalized`（实施时补，见实施文档 §6.1 偏离 4） | 在育儿室自由玩耍 |
| 母亲所在场景不可达 | 场景不在 `cache.scene_data` 里（未解锁/已拆除，实施时补） | 同上 |
| 母亲没有工作（`work_type == 0`） | `WorkType.csv` cid 0 | 跟着母亲但不产生见学经验，只加 `care_point` 与好感 |

**母亲在 H 时的回落是硬要求，不是优化**：既有的跟随链不会主动判 H 状态，本期必须显式加这一条。

### 9.1 见学与日程的缺口修补（2026-09-08）

一期第六轮盘完之后，用同一套机扫方法回头盘二期。这轮**换了三个扫描方向**，
扫出来的东西恰恰是上一轮那套方法**结构上看不见**的：

| 新的扫描方向 | 与上一轮的区别 | 扫出了什么 |
| --- | --- | --- |
| 字段 → **读取**点 | 上一轮扫的是字段 → 写入点 | `follow_mother_flag` 写三处、读**零**处 |
| 行为 → **口上覆盖率** | 上一轮只查代码符号，不查内容 | `free_play` 是全游戏 40 个娱乐类行为里**唯一**零口上的 |
| 口上前提 → **判定对象** | 上一轮只查前提是否注册，不查判在谁身上 | `have_work` 判的是行为发起者，而它想判的是母亲 |

**「有写入方」不等于「实装了」，「有注册」也不等于「判对了」。**
一期第六轮扫「字段→写入点」时，`follow_mother_flag` 三处写入全在，一路绿灯通过；
它的问题要换个方向才看得见。往后每加一个字段，两个方向都要扫一遍。

#### 9.1.1 `free_play` 零口上

`free_play`（行为 232）是实施二期时才加的（§6.1 偏离 3），方案 §2.6 只安排了
`follow_mother.csv` 的 10 条口上，加行为时没有回头补。结果它成了全游戏 40 个
娱乐类行为里唯一一个一条口上都没有的——玩家走进育儿室看见孩子在那儿，一个字都没有。

**零口上的行为是彻底静默的，不会回落到任何兜底。**
`choice_talk_from_talk_data`（[talk.py:256](Script/Design/talk.py#L256)）在候选为空时，
只有当行为在 `config_talk_common_cid_list_by_type`（纸娃娃地文表）里才有回落，
否则 `talk_text` 就是空串，什么也不打印。

而它偏偏是个高频行为，占了两个位置：

1. 幼女见学回落链的**唯一出口**——母亲在 H / 被监禁 / 外勤 / 住院 / 死亡 / 无母亲 /
   场景不可达，§3.24 的七种情形全部落到它
2. 「均衡」与「玩乐优先」两套预设模板的**晚上**时段

补 12 条，按年龄三档分差分（幼女 4 / 萝莉 4 / 少女 2）+ 2 条中立兜底。

**口上的前提列绝不能留空。** CSV 载入时空字段不会给配置对象建出属性，
`load_talk`（[game_config.py:1464](Script/Config/game_config.py#L1464)）读 `now_tem.premise`
会直接 `AttributeError`，**完整重建数据后游戏起不来**。v0.67 已经因为这个栽过一次
（性技实操课的三条到场/旁观口上），本轮写中立兜底时又踩了一次。
中立兜底用 `sys_1`（NPC 触发该指令）——`free_play` 恒由 NPC 触发，这个前提永真且语义正确。

#### 9.1.2 见学口上的「母亲有没有工作」此前分不开

`follow_mother.csv` 的 6 条「妈妈在干活」挂的是 `have_work`，但口上前提判的是
**行为发起者**（[talk.py:156](Script/Design/talk.py#L156) 传的是 `character_id`），
发起者是孩子。而孩子一长成幼女就被赋予 152「学生」岗
（[pregnancy_handle.py:565](Script/System/Pregnancy_System/pregnancy_handle.py#L565)），
`have_work` 于是**恒为真**。

实测两种母亲下候选池完全相同、都是 10 条：母亲没工作时照样出「妈妈干活的时候……」，
母亲有工作时照样出「今天妈妈没有工作」。**结算侧分得很对**
（`settle_follow_mother_gain` 查的是母亲的 `work_type`），只有口上这一层判错了对象。

根因是仓库里有 60 多个 `t_work_is_*` 目标侧前提，唯独缺通用的 `t_have_work`。
本轮补 `t_have_work` 与 `t_not_have_work` 两个。

**反向前提必须成对补，不能只补正向的。** 口上选取是加权随机不是最具体独占
（一期 §9.4 已记过同一条），只给「有工作」那 6 条加前提、「没工作」那 4 条不加，
结果是后者在两种情形下都出场。

#### 9.1.3 `follow_mother_flag` 只写不读

`CHILD_GROWTH` 的 19 个字段里唯一的只写字段。见学状态机里那行注释自己写着
「供口上前提与面板判定使用」，两个消费者一个都没建。这与一期 `report_card_flag`
是同一类半截链的**镜像**——那个有读无写，这个有写无读。

**口径 6 明写「不复用 `sp_flag.is_follow`，另建跟随字段」，所以正解是接上而不是删掉。**

接法三处：

| 消费者 | 说明 |
| --- | --- |
| `class_ai.judge_in_follow_mother()` | 统一读口。全岛绝大多数干员的 `child_growth` 是 `None`，外部直接读那个字段会 `AttributeError` |
| 角色状态标识 `<学>` | 照一期 `<课>` 的做法接进 `character_info_head.get_character_status_list`，一处改动同时覆盖 Tk 与 Web（Web 侧 `_get_special_states` 是 `zip` 遍历 + 跳过空串，加一格自动生效） |
| 前提 `self_follow_mother` | 用在新增的 `chat/chat_follow_mother.csv`（8 条）：见学中的女儿主动找博士说话时的专属地文 |

**标识用 `<学>` 不用 `<跟>`**：`<跟>` 已经是「智能跟随玩家」的标识，两者语义完全不同。

**置位一处、清位四处。** 置位只有见学状态机一处，清位却要覆盖所有离开见学的路径：
自由玩耍状态机、见学结算、**上课接管**、**见学判定不成立**，再加每日结算兜底。
其中「上课接管」那处最容易漏——`judge_class_state_machine` 排在见学判定**之前**，
幼女从见学转去上课时根本走不到 `judge_follow_mother_state_machine`，
少了它标记就会一直粘在孩子身上摘不掉。

**只补了自己侧的前提，没补目标侧。** `t_follow_mother` 一开始也写了，
但没有任何口上会用它——那正是本轮在清理的同一类债，于是删掉。
日后真要做「玩家对见学中的女儿发起互动」的差分口上时再补，六行的事。

#### 9.1.4 日程改写此前不校验娱乐的 `need`，以及 `need` 的素质条件一直判错素质

`apply_schedule_for_child` 只查 cid 在不在配置表里，不查 `need`。

**模板是全局共享的，而 `need` 是逐人的**——这是本节的要害。
「跟随母亲」(176) 配的 `need` 是 `T102|1` 只限幼女，同一套模板套到萝莉身上时，
不校验就会把 176 照写进她的 `entertainment_type`，而见学分支对萝莉不成立（口径 10），
那一格于是既不见学也不玩耍。

**引擎只在随机抽娱乐时校验过 `need`**（`handle_npc_ai.get_chara_entertainment`），
日程改写是**另一条写入路径**，必须自己校验。不满足时跳过该格，留当天的随机娱乐比空转强。

**接上校验之后，测试立刻暴露出一个更深的问题：连幼女都过不了 `T102|1`。**
`attr_calculation.judge_require`（[attr_calculation.py:965](Script/Design/attr_calculation.py#L965)）
的素质分支读的是 `talent[judge_value]`——把竖线**后面**那个「要求值」当成了素质 id。
而 `A`（能力）/ `J`（宝珠）/ `E`（经验）/ `O`（设施）四个分支读的都是竖线**前面**那个 id，
CSV 里的数据也全是按「id 在前」写的。也就是说全仓库仅有的三条素质条件，判的全是别的素质：

| 配置 | 本意 | 实际判成 |
| --- | --- | --- |
| `T7\|0`（品酒 62） | 非未成年 | 素质 **0 阴道处女** |
| `T103\|1`（过家家 151） | 是萝莉 | 素质 **1 肛门处女** |
| `T102\|1`（跟随母亲 176） | 是幼女 | 素质 **1 肛门处女** |

**总纲口径 52 写的「既有配置已经把品酒挡在孩子之外」实际上是反的**：
未成年角色只要还是处女就能去品酒，反倒是成年角色被挡住了。

改为按 `T<素质id>|<要求值>` 读，即 `talent[judge_type_id] != judge_value` 时不满足
（用 `!=` 而不是 `<`，`|0` 那一档要表达的是「必须没有这个素质」）。
**影响面正好是这三行**：全仓库的 CSV 里 `T<id>|<值>` 只出现三次，全在 `Entertainment.csv`，
所以这是一处小改动带来的行为回正，而不是一次波及全局的语义变更。
回正之后品酒只对成年角色开放、过家家只对萝莉开放，与两处配置写的一致。

#### 9.1.5 模板改为可增删改名，并给出「不套用」的出口

§1 的目标写的是「可定义**若干套**日常日程模板」、§4.2 的验证清单写的是
「能**新建**、编辑、批量套用」，而实装是固定 4 套。补上新建 / 重命名 / 删除。

**四套预设不可删**：`init_default_template` 只在整张表为空时才补，
删掉一套预设不会被补回来，而 `PRESET_TEMPLATE_NAME` 的编号在代码里被引用着。预设可改名、可改内容。

**新编号从既有最大编号往后顺延，不补空缺号**：孩子身上存的是模板编号，
删掉 5 号之后把新模板也叫 5 号，会让原来套 5 号的孩子凭空套上一套完全不同的日程。

**删除前必须把引用它的孩子解开**，否则那些孩子的 `schedule_template_id`
指向一个不存在的编号。

另外补上「不套用日程（恢复随机）」的出口：`apply_template(character_id, 0)` 数据层
一直支持，只是面板没给按钮——少了它，孩子一旦套上日程就再也回不到「每日随机娱乐」。

#### 9.1.6 批量套用的名单此前会列出全岛干员

`get_child_candidate_list` 用的是 `growth_handle.judge_is_child`，它**只看素质**。
而世界设定「萝莉化」(`cache.world_setting[1]`) 会把全岛干员的年龄素质改写为萝莉 103
（[character_handle.py:434](Script/Design/character_handle.py#L434)），于是这份名单会列出整个罗德岛。

一期 `get_student_candidate_list` 的注释里**逐字写过这个陷阱**
（"只按素质筛会把全岛的人都塞进课表页签栏"），二期这个函数还是掉了进去。
**同一个语义只留一个实现**：删掉 `get_child_candidate_list`，面板改走一期那个。
顺带把婴儿也挡掉了——婴儿排不了自习读书。

#### 9.1.7 口径 25 / 32 由三期兑现，二期不该认领

二期方案的口径行原本列了 25（孩子之间有互动）与 32（养成事件每日入队量），
但二期的三个目标里没有任何对应内容，§8 的范围外还明写「养成事件系统 → 三期」。
这两条实际由三期兑现（`get_sibling_child_list` / `get_classmate_list` +
38 条用了兄弟姐妹/同学前提的公务事件）。本轮从二期的认领清单里摘掉，只在三期保留。

### 9.2 第二轮追加调整：选活动改版、编号与限制、萝莉见学、总览阶段行、选人按钮（2026-09-09）

收尾总检查（总纲 §8）之后用户实机体验，提出 7 条调整（需求 → 落点表见总纲 §9）。本节记设计层面的取舍。

#### 9.2.1 「选择活动」面板改为三组，时段值 0 显示为「自由选择娱乐活动」

原第一行固定 上课（无课时自习）/ 自由玩耍 / 跟随母亲 三项。用户要的是：第一行的「自由玩耍」换成「自由选择娱乐活动」——不是指定某项娱乐，而是**该时段不改写、保留当天随机娱乐**；自由玩耍则和其他娱乐一样往下放。

「自由选择」在数据上就是既有的时段值 0（`set_template_slot(..., 0)` 与「清空该时段」一直是这个语义），所以不新增娱乐行，只给 0 一个显示名 `SCHEDULE_FREE_CHOICE_NAME`，模板表、编辑页、个人日程摘要里原来的「--」「未设置」统一改显示它；原「清空该时段」按钮与它同值，并掉。

三组的划分不写死：第二行 = need 列里带成长阶段素质条件（`T<101~104>|1`）的活动，由 `get_activity_age_limit_talent_list` 现算，按钮上再拼一个「限幼女/萝莉」。现算出来正好是过家家 / 跟随母亲 / 自由玩耍三项；日后再加一项有年龄需求的活动，面板自动跟上。

**单孩覆盖存不了 0**：`set_child_override(cid, slot, 0)` 的语义一直是「取消这一格的单独指定」。日程微调页里选「自由选择娱乐活动」于是等于回到模板的安排，不是强制自由选择。没有为此改数据结构（那要再加一个「取消单独指定」的出口，超出本轮范围），只在微调页加了一行提示把话说明。

#### 9.2.2 教育区娱乐改到 15x 段，限制条件写进 need 列

娱乐编号按「区块 id × 10 + 序号」分段（05x 生活娱乐区、09x 训练场、10x 图书馆、11x 贸易区、15x 教育区、17x 大浴场）。照料卵 175、跟随母亲 176、自由玩耍 177、上课 178 四项的地点都在教育区，却排在大浴场段，本轮改到 152~155 紧接 151 过家家。

限制条件按用户要求落在数据上，`attr_calculation.judge_require` 加两个通用语法：

| 语法 | 含义 | 用在 |
| --- | --- | --- |
| 同一项内 `/` | 「或」，子条件逐个递归交回 `judge_require` 判定，任一满足即可；全不满足时 reason 用「或」连接 | 过家家 / 跟随母亲 / 自由玩耍 `T102|1/T103|1`（限幼女或萝莉） |
| `W<岗位id>|1` / `|0` | 当前岗位是 / 不是该岗位 | 上课（无课时自习）`W152|1`（限学生岗） |

两者向后兼容：全仓库既有的 need 串从没用过 `/`，六个调用点零改动。这套限制只管**日程改写**（`apply_schedule_for_child` 逐人校验，不满足就跳过、保留随机值——这就是「退回到自由选择娱乐活动」，个人课表的日程行与微调页把这种时段标成「X（条件不符→自由选择）」）；每日随机娱乐池另有自己的 need 校验与 `SCHEDULE_ONLY_ENTERTAINMENT_SET` 排除表，幼女的随机娱乐仍固定为过家家。

顺手清理：`handle_premise_entertainment` 的「大浴场类娱乐」集合原来写的是 `{171,...,176}`，把照料卵 175 与跟随母亲 176 也算成了浴场娱乐（改编号后更是悬空引用），改为 `{171,172,173,174}`。`handle_npc_ai.get_chara_entertainment` 里的四处字面量（151 / 175 / 176~178）全部改引常量，`education_constant` 只能在函数内延迟 import。

#### 9.2.3 萝莉按日程可见学

「跟随母亲」放宽到萝莉之后，若见学分支仍只认幼女，萝莉排了它的时段会空转。用户拍板：萝莉**按日程**可见学——`judge_should_follow_mother` 改为：有课永远优先；幼女在节次内没课默认见学（不变）；幼女的课外时段与萝莉的全部时段，只看当前娱乐时段的日程是不是「跟随母亲」。口径 10 的「萝莉自由时段自由行动」仍是默认，只是多了一个玩家主动排出来的入口。状态机 717/718/719、效果 553/554 与 `follow_mother.csv` 的口上都没有年龄门，萝莉走进去零改动。

#### 9.2.4 养成总览的阶段行：母亲、剩余天数与预计日期

原来写「本阶段已成长 N 个可游玩天」——数字其实是 `get_child_grow_day` 的日历天，标注还写反了。改为一行「母亲：X｜当前阶段：幼女｜距成长为萝莉还有 N 天（日历天），预计 2026年秋月12日 抵达」：剩余天数 = 阶段阈值 − 成长天数（都由妊娠系统统一算，含成长加速药），预计日期从今天往后数、走 `game_time.get_predict_date` 归并到季月（非季月会被时钟整段跳过）。已成年不写天数；持成长停滞素质 28 时写「成长停滞中，阶段不会推进（解除后还需 N 天）」——停滞期间 `check_grow_to_*` 不推进阶段，给预计日期只会误导。母亲取 `relationship.mother_id`，无效时显示「未知」。

#### 9.2.5 个人课表与养成总览改为「选择学生」按钮

一期 §9.8.1 的每页 8 人页签栏整体取代：两个面板的首屏只有一行「尚未选择学生 [选择学生]」（`student_select.draw_select_student_line`），不再默认回落到名单第一个；点按钮走 `common_select_NPC.common_select_npc_button_list_func`（`student_select.select_student`），名单由面板预筛后传入——个人课表 = 学生岗 ∪ 女儿，养成总览 = 养成中的女儿——玩家在通用面板里再按收藏 / 名字 / 区块筛一遍挑人。选中者失效（长大、换岗）时清回未选择。

#### 9.2.9 幼女 / 学生「没课的节次」行为链修正（2026-09-10）

**查证**：`find_character_target` 的顺序是 预到岗 → 课表 → 见学 → 工作链 → 娱乐链。三处叠在一起，让日程模板的上午 / 下午时段对孩子从不生效：

| 对象 | 上午 / 下午没课的节次实际去向 | 日程的上午 / 下午槽位 |
| --- | --- | --- |
| 幼女 | `judge_should_follow_mother` 在课表节次内（9:00~12:00、14:00~17:45；`get_class_period` 不看星期，周末也算）只要没课就一律见学 | 从不生效，只有晚上生效 |
| 萝莉 / 少女 / 成年学生 | 学生岗 152 `have_work` 为真、周一~周六到岗时间走工作链，`WorkType.csv` 152 的自动 AI 把人送进随机一间理论教室「上学」（行为 214 学生侧只有 1511 / 1512，学习收益只由教师授课的 512 遍历发放，没老师就是零）；`all_entertainment_time` 对有工作的人周一~周六只认 19~22 | 周一~周六不生效，周日生效 |

另：`apply_schedule_for_child` 要求整段没课才改写，上午只要有一节课整个上午的日程都不生效；幼女三个槽位固定写过家家。这些与口径 9 / 10「未排课的节次自由行动」、§3.6「日程管的是没有课的时段」、一期方案 §3.4 都不符。

**用户确认的三条口径**：幼女白天没课的节次**明确排了的日程优先**（排「跟随母亲」或「自由选择」才默认见学，有课的节次仍课表优先，改写不再要求整段没课）；学生岗没课的节次**不走工作链**、白天也算娱乐时间（排了日程做日程，没排做当天随机娱乐）；幼女没排日程时每个时段在**过家家 / 自由玩耍之间随机**。

**落点**：

- `class_ai.judge_should_follow_mother`：先看槽位是否为「跟随母亲」（入口2，幼女 / 萝莉共用）；再走幼女的入口1，但 `schedule_template_handle.get_child_slot_activity` 给出的模板值非 0 且与槽位实际值一致（= 已排且 need 通过）时不见学，交给娱乐链。「自由选择」与「活动没写进槽位」都算默认见学。8:40~9:00、17:45~18:00 不在娱乐时段，只认入口2。
- `handle_npc_ai.find_character_target`：工作链条件加 `work_type != STUDENT_WORK_TYPE`。`target.csv` 的 21 / 22 类工作目标都带 `work_is_xxx` 前提、没有学生岗的，通用搜索不会把学生送去工作。学生此前也没有到岗前移动（`npc_auto_work_or_entertainment` 的 `work_time` 前提 8:40 时不满足），没有损失。
- `handle_premise_time._judge_free_daytime`：非工作日 / 无工作 / 学生岗三者任一 → 白天也算娱乐时间，`all_entertainment_time` 与 `not_all_entertainment_time` 共用；学生岗 id 延迟 import `education_constant`。`target.csv` 31~33 类娱乐目标与 `npc_auto_work_or_entertainment` 都走这个前提，自然一致。
- `get_chara_entertainment`：幼女每个槽位 `random.choice(CHILD_DEFAULT_ENTERTAINMENT_LIST)`（过家家 / 自由玩耍）。
- `apply_schedule_for_child`：去掉整段没课的门槛，删除 `judge_slot_free_of_class` 与 `SLOT_PERIOD_RANGE`。

**验证**：`test_class_ai.py` 新增「日程优先于幼女默认见学」四条与「没课节次的去向」一段——后者用一个包装 `constant.handle_state_machine_data` 的 `dispatch()` 直接跑 `find_character_target`，断言萝莉 / 幼女周一上午没课时被派去育儿室（564 / 719）或教室自习（561 / 713）、自由选择的幼女去母亲身边（717）；`test_schedule_template.py` 改为「有课也照写」并新增幼女默认池。不改 CSV、不需要存档迁移。
