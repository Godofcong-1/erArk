### 2.2 关键发现：排版由**字体字宽**决定，不是 `wcswidth`

`line.width` 走 `Script/Core/text_handle.py:65 get_text_index()`（即 `wcwidth.wcswidth`），但**它不参与行内排版**：`see_map_panel.py:97-109` 只用全局 `max_width` 算出**一个所有行共用**的 `fix_width` 空格前缀，然后逐段原样输出。因此**行内对齐 100% 由字体的实际字宽决定**。

用 `tkinter.font.Font(family="等距更纱黑体 SC", size=20).measure()` 实测（`font_size = int(window_width / text_width) * 2 = int(2000/190)*2 = 20`），并已确认字体测量可加（整串测量 == 逐字累加）：

| 字符类 | 实际像素宽 | `wcswidth` |
| --- | ---: | ---: |
| 框线 `═║│┃┄┅┆┇─━`、`▓ ♀ ♂ ¤ ▁` | **13** | 1 |
| ASCII 空格、`~`、`-`、数字 | **14** | 1 |
| 汉字、`○ ● □ ▣ ♲ － ◎` | **26** | 1 或 2 |
| `☸ ➷ ➹ ✪` | **28** | 1 |

**根因**：框线是 13px 而 ASCII 空格是 14px，两者不通约。地图里每出现一个 ASCII 空格就相对框线漂移 1px，一行几十个空格就能把竖墙推歪十几个像素——这正是实机截图里看到的错乱。

进一步实测不同字号后发现，这个偏差**只在部分字号出现**：

| 字号 | 12 | 14 | 16 | 18 | **20** | 22 | 24 | 26 | 30 | 40 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| ASCII 空格 | 8 | 10 | 11 | 12 | **14** | 15 | 16 | 18 | 20 | 27 |
| 框线 `═` | 8 | 9 | 10 | 12 | **13** | 15 | 16 | 18 | 20 | 26 |
| 是否相等 | ✓ | ✗ | ✗ | ✓ | **✗** | ✓ | ✓ | ✓ | ✓ | ✗ |

也就是说，全项目地图沿用的“空格 == 框线 == 1 列”这个约定，在字号 18/22/24/26/30 下碰巧成立，在 **14/16/20/40 下不成立**；而当前 `config.ini`（`window_width=2000`、`text_width=190`）恰好落在字号 20 这个坏值上。

## 4. 排版模型：以框线宽度为 1 个单位 U

令 **U = 框线字符的宽度**。只使用宽度**恒为 1U 或 2U**的字符，地图就能在任意字号下严格对齐（已在 12/14/16/18/20/22/24/26/30/40 共 10 个字号下验证）。

### 4.1 安全字符白名单（实测恒定）

| 宽度 | 可用字符 |
| --- | --- |
| **1U** | 框线 `═ ║ │ ┃ ┄ ┅ ┆ ┇ ─ ━`、`▓ ♂ ♀ ¤ ▁`、**U+2002 EN SPACE（留白）**、`≈ ∼ ∽ ⊙ ⊕` |
| **2U** | 全部汉字、`○ ● □ ▣ ♲ ◎ ◉ ◍ ◇ ◈`、`～ 〜 ﹏ ⌒`、`← → ↗ ↘ ↖ ↙`、`－ ＿ ＜ ＞`、U+3000 全角空格 |

### 4.2 禁用字符与本次的取舍

属 ASCII 度量族、与框线不通约的字符：**ASCII 空格**、`~`、`-`、数字与字母、`☸ ➷ ➹ ✪`。

本次的替换与保留：

| 原字符 | 处理 | 说明 |
| --- | --- | --- |
| ASCII 空格 | → **U+2002 EN SPACE** | 全图 557 处留白，ASCII 空格已归零。这是消除大范围错位的关键 |
| `~`（泳池水面） | → `∼` U+223C | 1U |
| `-`（饮水机出水口） | → `─` U+2500 | 1U |
| `☸`（靶心） | → `◎` U+25CE | 2U，语义更贴切且完全对齐 |
| **`➷` `➹`（弹道）** | **保留原字符** | 按需求保留观感；代价见下 |

**保留 `➷➹` 的确切代价（已实测，非估计）**：

- `➷`/`➹` 在当前字号下是 28px，而 2U = 26px，因此**每个箭头让所在行多出 2px**。
- 两个箭头分别位于第 2 行与第 4 行的**靶道格内**（全图最右侧的格子）。
- 因此**左侧四条竖墙（像素列 0 / 27U / 46U / 55U）在所有行、所有字号下都完全对齐**；受影响的只有第 2、4 行**最右端的 `┃`**，相对边框右移 2px。
- 该偏差随字号变化：字号 12/18/22/24/26/30 下为 **0px**，字号 14/16/20/40 下为 **2px**。
- 校验命令用 `--tol 2` 即可通过：`python tools/map_aa_check.py 训练 --tol 2`

> 另有一处 1px：走廊标签行末尾的入口按钮 `0` 是 ASCII 数字（场景目录名不可改）。该行没有任何竖墙，不产生可见错位。

## 7. 工具脚本、生成与校验

### 7.1 `tools/map_aa_build_training.py` —— 训练场地图生成器

```bash
python tools/map_aa_build_training.py            # 生成并写入 data/map/训练/Map
python tools/map_aa_build_training.py --dry-run  # 只打印，不写文件
```

按 U 单位拼装 14 行，写入前自检三件事：每个竖墙行必须 89U、不得含 ASCII 空格、不得含裸尖括号。任一不满足就报错退出、不写文件。要调整版面就改这个脚本，不要手改 `Map`。

### 7.2 `tools/map_aa_check.py` —— 逐像素对齐校验器（对所有地图通用）

```bash
python tools/map_aa_check.py                  # 校验全部地图
python tools/map_aa_check.py 训练 --tol 2     # 校验训练场，允许 2px 容差
python tools/map_aa_check.py --list-bad       # 按错位严重程度列出全部地图
```

在 10 个字号下逐字符累加像素位置，检查：① 所有含竖墙的行总宽是否一致；② 结构相同的行（竖墙数量相同）每一堵墙是否落在同一像素。超出容差则打印具体是哪几行、哪堵墙差了多少，并以退出码 1 结束（可直接接进 CI）。

**训练场的期望输出**（`--tol 2` 通过）：

```text
字号 12：竖墙行总宽 [712] px
字号 14：竖墙行总宽 [801, 803] px
字号 16：竖墙行总宽 [890, 892] px
字号 18：竖墙行总宽 [1068] px
字号 20：竖墙行总宽 [1157, 1159] px      ← 当前字号
字号 22：竖墙行总宽 [1335] px
字号 24：竖墙行总宽 [1424] px
字号 26：竖墙行总宽 [1602] px
字号 30：竖墙行总宽 [1780] px
字号 40：竖墙行总宽 [2314, 2316] px
```

两个值的字号里，多出的 2px 全部来自第 2、4 行的 `➷` `➹`（见 §4.2）；左侧四条竖墙在所有字号下都是单一值。

## 8. 风险与回滚

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 手改 `Map` 导致 U+2002 变成普通空格 | 会立刻退化成 v2 那种大范围错位 | 一律改脚本重新生成，再跑 §7.2 校验 |
| 换字体 | 白名单是针对 `等距更纱黑体 SC` 实测的 | `map_aa_check.py` 直接读 `config.ini` 的字体，换字体后重跑即可 |
| Web 模式字体回退 | CSS 回退到 Consolas 时 U+2002 与框线的比例可能变化 | 与现有地图同等风险，需实测 |
| 忘删四个缓存 | 改动完全不生效，且没有任何报错提示 | §7.3 |
| 只改 AA 不改 Scene.json 时老档不刷新 | `save_handle.py:516` 受 `change_map_flag` 保护 | 本次新增了 Scene.json，不受影响 |
| 按钮名与目录名不符 | `map_handle.py:363` 无限递归 `RecursionError` | 目录名必须正好是 `休息室` |

**回滚**：`git checkout -- data/map/训练/Map data/map/训练/Map.json update.log`、删除 `data/map/训练/休息室/`，再删四个缓存重建。
